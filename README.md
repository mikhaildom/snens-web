# snens/web

Веб-клиент агента snens: живой транскрипт сессии. Не окна мессенджера, а лента —
реплика человека, свёрнутая пачка шагов, ответ модели. Данные — API ядра
(`snens serve`, loopback:7420). Стиль: брутализм, моноширинный JetBrains Mono,
ноль радиусов, темы `auto`/`light`/`dark` в CSS-переменных.

## Запуск

```sh
npm i
npm run dev      # http://100.73.69.107:5174 (tailscale, наружу не торчит)
SNENS_WEB_PORT=5175 npm run dev   # свой порт: 5174 — рабочий порт человека
npm run build    # tsc -b && vite build
npm test         # правила ленты (src/lenta.test.ts)
npm run lint     # oxlint
```

Dev-сервер проксирует `/api` → `127.0.0.1:7420` и подставляет Bearer из
`~/.local/share/snens/api.token`, поэтому токен не попадает в бандл.
Переопределить: `SNENS_API_BASE`, `SNENS_API_TOKEN_FILE` (см. `vite.config.ts`).

Параметры адреса: `?session=<id>` — открыть сессию, `?nostream=1` — снимок без
SSE (скриншоты, отладка), `?dock=1` — док раскрыт, `?theme=light|dark|auto` —
разовый просмотр без записи в `localStorage`.

## Карта

```
src/
  api.ts          клиент /v1: типы, запросы, SSE-подписка, uuid для command_id
  lenta.ts        правила ленты: applyEvent (SSE → живая лента),
                  collectTools (вызов+результат → ToolRun), buildBlocks (что видно, что свёрнуто)
  markdown.tsx    markdown-it (html выключен) + KaTeX
  theme.ts        тема: url/параметр → localStorage → data-theme на <html>
  settings.ts     настройки отображения (показ справки памяти)
  useResize.ts    тяга краёв rail/дока с сохранением ширины
  App.tsx         состояние сессии и раскладка; разметки почти нет
  hooks/          эффекты, вынутые из App: useActiveSession (?session и replaceState),
                  useSessions, useTranscript (история + SSE), useContextWindow, useSearch (дебаунс)
  lib/            чистые функции: time (time/dur/relTime), format (stepsWord/shortArgs/fileUrl),
                  tool (MARK/hasMedia/viewedPaths/argLabel), parts, context (лимит окна)
  feed/           лента: Feed (блоки + approval/error), turns (Step/UserTurn/Say), Fold,
                  ToolBlock, media (Lightbox/Shots/Voices), Attachments, UsageBar, Recall, Live, Head
  dock/           Dock (табы окна/тулы), ToolRow, ContextWindow (окно контекста), Agents (подагенты)
  rail/           Rail (поиск, список, удаление), Topbar, Statusbar
  composer/       Composer: черновик, вложения, drag&drop
  settings/       SettingsBar + ThemeBar
  styles/         CSS по слоям; порядок @import в index.css = приоритет каскада
```

Конвенции, которые стоит держать:

- компонент получает данные только пропсами (никаких импортов состояния из App);
- правила ленты живут в `lenta.ts` и покрыты `lenta.test.ts` — не размазывать их по
  компонентам; новый тип события SSE добавляется туда же, в `applyEvent`;
- форматы подписей (`relTime`, `dur`, `stepsWord`) — только из `lib/`, не дублировать;
- новый CSS-слой = новый файл в `styles/` и строка `@import` в нужном месте порядка.

## Что умеет

- Список и создание сессий, история из журнала JSONL, отправка сообщения,
  stop (нужен `run_id`), SSE-стрим дельт и тулов, карточка одобрения sudo.
- Поиск по журналам (дебаунс 300 мс), удаление сессии с подтверждением,
  заголовок вкладки по заголовку сессии.
- Лента: реплика → свёрнутая группа шагов («N шагов · M рассужд. · время») →
  финальный ответ. Reasoning свёрнут по умолчанию и у промежуточных шагов, и у
  финального (хронологически он до текста ответа, поэтому уезжает в группу).
- Вызов инструмента и его результат — один блок: имя, аргументы, exit, время,
  раскрывается в argv + вывод + вложения. Картинки/видео из канала вложений
  (`view`) и голосовые человека играются
  (`GET /v1/sessions/{id}/file?path=…`), картинки открываются лайтбоксом.
- Стрим и история рисуются одним кодом: живая лента (`liveSteps` в `lenta.ts`)
  группируется в те же шаги, что даёт журнал, поэтому переход «стрим → история»
  не перерисовывает ленту. Расход шага (`usage` в SSE) и вложения тула приходят
  в стриме тоже.
- Автоскролл держит низ, только пока человек там: отлистал вверх — лента не
  дёргается, появляется кнопка «↓».
- Саморевью: маркер `role: "review"` («саморевью · N ходов») рисуется тонкой серой
  строкой в хронологии — это граница зоны ответственности следующего ревью.
- Рендер markdown: `$…$`, `$$…$$`, `\(…\)`, `\[…\]` через KaTeX. Картинки из
  markdown рисуются только в ответах модели; в выводе тулов остаются alt-текстом —
  `fetch` тащит со страниц десятки иконок.
- Справа док с табами «окна» (подагенты) и «тулы» (логи прогонов), сверху шкала
  окна контекста. <1240px док становится полноэкранной шторкой (кнопка «док»).
- Края rail и дока тянутся мышью, ширина живёт в `localStorage` (`snens-rail-w`,
  `snens-dock-w`), двойной клик по краю или стрелки — сброс/шаг.
- Контекст (модель, cwd, ходы, токены) — в статус-строке под composer'ом.

## Грабли

- `crypto.randomUUID` есть только в secure context: по `http://100.73.69.107:5174`
  его нет — в `api.ts` поэтому свой `uuid()` с фолбэком.
- Сессия в адресе обновляется через `replaceState`: `pushState` на каждый клик
  забивал историю браузера.
- Живая лента — один массив (`LiveItem[]`), порядок вставки = хронология.
  Раздельные «stream» и «словарь тулов» перетасовывали блоки на каждом шаге модели.
- `spellCheck=false` в composer'е осознанно: браузер проверяет поле по языку
  страницы, а текст смешанный.
