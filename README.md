# snens/web

Мокап веб-клиента snens. Не окна, а транскрипт: сообщения разделены левой линейкой
(у `you` — акцентная, у тулов/системы — волосяная), фон общий с полотном.
Стиль — брутализм, только моноширинный (JetBrains Mono, локально через @fontsource).
Тема: `auto` (по системе) / `light` / `dark`, живёт в CSS-переменных и `data-theme` на `<html>`.

```sh
npm i
npm run dev      # http://100.73.69.107:5174 (tailscale, наружу не торчит)
```

- `?theme=light|dark|auto` — разовый просмотр без записи в localStorage.
- `?session=<id>` — открыть конкретную сессию, `?nostream=1` — без SSE, `?dock=1` — док раскрыт.
- Справа — док с табами: «окна» (подагент, webview, документ) и «тулы» (раскрываемые логи прогонов).
  <1240px док становится полноэкранной шторкой (кнопка ▤ в топбаре).
- Края rail и дока тянутся мышью, ширина живёт в `localStorage` (`snens-rail-w`, `snens-dock-w`),
  двойной клик по краю или стрелки на нём — сброс/шаг.
- Контекст (модель, cwd, ходы, токены) — в статус-строке под composer'ом.
- Данные — живой API ядра: `snens serve` на loopback:7420 (`src/api.ts`).
  Dev-сервер проксирует `/api` → `127.0.0.1:7420` и подставляет Bearer из
  `~/.local/share/snens/api.token`, поэтому токен не попадает в бандл.
  Переопределить: `SNENS_API_BASE`, `SNENS_API_TOKEN_FILE` (см. `vite.config.ts`).
- Работает: список/создание сессий, история (журнал JSONL), отправка сообщения,
  stop (нужен run_id), SSE-стрим дельт и тулов, карточка одобрения sudo.
- Рендер: markdown (markdown-it, html выключен) + KaTeX для `$…$`, `$$…$$`,
  `\(…\)`, `\[…\]`. Картинки из markdown рисуются только в ответах модели;
  в выводе тулов остаются alt-текстом — `fetch` тащит со страниц десятки иконок.
- Лента: реплика человека → свёрнутая группа шагов («N шагов · M тул. · время»)
  → финальный ответ. Reasoning свёрнут по умолчанию и у промежуточных шагов, и
  у финального (уезжает в группу: хронологически он до текста ответа).
- Вызов инструмента и его результат — один блок: имя, аргументы, exit, время,
  раскрывается в argv + вывод + вложения. Картинки/видео из канала вложений
  (`view`) и голосовые человека показываются с проигрыванием
  (`GET /v1/sessions/{id}/file?path=…`).
- Заголовки сессий — из `title` (ядро) или первых слов первого сообщения;
  разницы «legacy / не legacy» больше нет: локальные сессии — `local`.
- Дока-окна («подагенты, браузер, документ») — заглушка: ядро пока не отдаёт
  список дочерних процессов через API.
